# OMNI INNOVATIONS

Mathematics across universes, creative tools born from the same philosophy, and anything else that treats "omniversal" as a design principle -- meaning it works everywhere, for everyone, with zero dependencies.

Three projects so far. One defines a formal mathematical notation for describing transformations across dimensional spaces. One implements nine mathematical universes in a single calculator. One is a creative writing tool with built-in AI collaboration. What they share: each is a single file, each runs in any browser, each does something that previously required specialized software -- and each does it with genuine depth, not a toy demo.

## What Belongs Here

Anything that embodies the omniversal philosophy -- tools and systems that are universal in scope and zero in dependencies:

- **Mathematical tools** -- calculators, visualizers, proof assistants, notation systems, and anything else that makes mathematics more accessible or more powerful
- **Creative tools** -- writing, drawing, diagramming, brainstorming, and other creative applications that run anywhere without installation
- **Theoretical foundations** -- formal notation systems, mathematical frameworks, and specification documents that define new ways of thinking about problems
- **Educational systems** -- interactive learning tools for math, science, writing, or any other domain where doing beats reading
- **Universal utilities** -- tools that solve real problems with zero dependencies, zero configuration, and zero learning curve before first use

The constraint that ties everything together: **zero dependencies**. Every tool in this folder should be a single file (or a self-contained directory) that runs in any modern browser or any Python environment without installing anything. If it needs `npm install`, it doesn't belong here. The point is radical accessibility -- anyone, anywhere, on any device, can use these tools by opening a file.

## What Doesn't Belong Here

Projects that require package managers, build steps, external services, or API keys to function. The AI Mode in Omni Writer is an optional enhancement that requires an API key -- but the core writing tool works perfectly without it. That's the model: full functionality with zero setup, optional enhancement for those who want it.

## Adding a Project

1. Create a subdirectory with a clear project name
2. Add a markdown file inside it describing the project, its current state, and how to run it (follow the `*ME.md` naming pattern -- `CALCULATEME.md`, `WRITEME.md`, `MATHME.md`, `SOLVEME.md`, whatever fits)
3. Add a row to the project table above
4. Update the root `README.md` with a bullet point under the OMNI INNOVATIONS section

The zero-dependency constraint is non-negotiable. Everything else is flexible. Some projects will be theoretical specifications. Some will be full applications. Some will be single-purpose utilities. All are valid as long as they open and work.

## The Omni Standard

The word "omniversal" isn't marketing. It's a design constraint. A tool that only works on one platform, in one browser, with one screen size, for one kind of user -- that's not omniversal. A tool that works everywhere, for everyone, immediately -- that is.

This means: responsive design that works on a phone and a 4K monitor. Dark themes that don't burn eyes at 2am. Keyboard shortcuts for power users and visible buttons for beginners. localStorage persistence so nothing is lost. Export in open formats so nothing is trapped. The user's work belongs to the user, always.

The deeper principle: mathematics is universal. Writing is universal. The tools for doing both should be too. No paywalls, no accounts, no telemetry, no "sign up to save your work." Open a file. Do the thing. Close the file. Everything is still there next time.
