# Undertale Innovations

Projects that take the Undertale universe seriously.

Not "Undertale but with my OC." Not "Sans fights Goku." This is the folder for fan games, revivals, engine experiments, rom hacks, AU toolkits, battle system prototypes, music remixes with actual arrangement work, and anything else that engages with what made Undertale matter -- the writing, the music, the systems, the way it made you feel responsible for things a game had never made you responsible for before.

## What Belongs Here

Anything that treats Undertale as a starting point, not a punchline:

- **Fan games** -- original stories set in or inspired by the Undertale universe, built with real game engines and real design documents
- **Revivals** -- abandoned fan projects brought back to life with modern tools and realistic scope
- **Engine experiments** -- battle systems, dialogue systems, overworld mechanics, encounter designs that explore what Undertale's design philosophy looks like in different contexts
- **Tools** -- level editors, dialogue tree builders, sprite animators, anything that makes it easier to build in this space
- **Music** -- compositions and arrangements that understand why Undertale's soundtrack works (leitmotif, emotional arc, genre-blending) and apply those principles to new material
- **Mods and hacks** -- modifications to existing Undertale/Deltarune builds that add, change, or reinterpret content
- **Research and analysis** -- deep dives into Undertale's design, writing, music theory, or game mechanics that produce something concrete (a document, a tool, a prototype)

If it's creative, it's honest, and it takes the source material seriously, it belongs here.

## What Doesn't Belong Here

Low-effort memes. Asset flips. Projects that use the Undertale name for attention but don't engage with what makes the games interesting. This isn't about gatekeeping -- it's about maintaining a standard where everything in the folder is something someone put real thought into.

## Adding a Project

1. Create a subdirectory with a clear project name
2. Add a markdown file inside it describing what the project is, what state it's in, and how to run or build it (follow the `*ME.md` naming pattern -- `OVERME.md`, `BATTLEME.md`, `COMPOSEME.md`, whatever fits)
3. Update this file's project table
4. Update the root `README.md` with a bullet point under the Undertale Innovations section

No required structure beyond that. Some projects will be full game engines with dozens of source files. Some will be a single prototype script and a design document. Both are valid. Just keep it documented.

## The Undertale Standard

Undertale succeeded because every system served the story. The bullet hell combat wasn't there because bullet hell is cool -- it was there because dodging attacks creates a physical empathy with the characters you're trying to spare. The save system wasn't a convenience feature -- it was a narrative device. The soundtrack didn't just set mood -- it carried character identity through leitmotif.

Any project in this folder should aspire to that level of intentionality. The bar isn't "as good as Undertale." The bar is "thought about *why* things work, not just *what* to copy."
